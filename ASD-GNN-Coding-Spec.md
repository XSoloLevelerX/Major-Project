# ASD-GNN — Coding Specification
### Engineering scope only. No literature, no report structure — just what gets built, in what order, with what contracts.

---

## 0. How to use this document

Every module below has: **inputs → outputs → signature → gotchas → the test that proves it works.** Build strictly in the order of §6. Do not start a module until the previous one's test passes.

Two rules that override everything else in this file:

1. **Nothing fits on test data.** Not the scaler, not the tangent-space reference, not the feature selector, not ComBat, not the PCA. If a `.fit()` call can see a test index, the project is invalid.
2. **Every result is a JSON file on disk.** No numbers live in notebooks or in your head. Tables are generated by a script.

### 4.3 `data/timeseries.py`

```python
def load_timeseries(paths: list[str], pheno: pd.DataFrame) -> dict[int, np.ndarray]:

def qc_filter(

```

Loader body:

```python
arr = np.loadtxt(path)          # numpy skips '#'-prefixed header lines automatically
if arr.ndim != 2:
    raise ValueError(f"bad shape {arr.shape} in {path}")
```

**Gotchas — this module produces more silent bugs than any other**
- **Time series lengths differ across sites** (78 to 300+ frames). Never assume a fixed `T`. Correlation handles variable length fine; anything that stacks along time does not.
- **Constant / all-zero ROI columns.** Some CC200 parcels fall outside a subject's brain mask → zero variance → `NaN` in the correlation matrix → `NaN` loss → silent training failure. Handle it: identify ROIs that are constant in *any* subject, drop that ROI column globally (consistent node set across subjects is required for brain graphs), and log how many you dropped. Expect to lose a handful with CC200.
- Cast to `float32` immediately. `float64` triples your memory for no benefit.
- Log every dropped subject with a reason into `results/qc/dropped.json`. You will need this for the paper's flow diagram.

**Test:** `test_shapes.py::test_timeseries` — all arrays 2-D, second dim identical across all subjects, no NaN, no zero-variance columns after filtering.

### 4.4 `data/connectivity.py` — **leakage-critical**

This module is where most student ABIDE projects break. Read it twice.

```python
from nilearn.connectome import ConnectivityMeasure
from sklearn.base import BaseEstimator, TransformerMixin

class ConnectivityTransformer(BaseEstimator, TransformerMixin):
    """sklearn-compatible so it can live inside a Pipeline and be fold-aware.

    kind: 'correlation' | 'partial correlation' | 'tangent'
    fit(X)  where X is a LIST of (T, R) arrays for TRAINING subjects only
    transform(X) -> (n, R*(R-1)/2) if vectorize else (n, R, R)
    """
    def __init__(self, kind="correlation", vectorize=True, fisher_z=True):
        self.kind, self.vectorize, self.fisher_z = kind, vectorize, fisher_z

    def fit(self, X, y=None):
        self.cm_ = ConnectivityMeasure(
            kind=self.kind, vectorize=self.vectorize, discard_diagonal=True
        )
        self.cm_.fit(X)                 # <-- TRAIN SUBJECTS ONLY
        self.n_fit_samples_ = len(X)    # <-- asserted by the leakage test
        return self

    def transform(self, X):
        Z = self.cm_.transform(X)
        if self.fisher_z and self.kind == "correlation":
            Z = np.arctanh(np.clip(Z, -0.999999, 0.999999))
        return Z
```

**Why this matters concretely:** `kind='tangent'` estimates a group geometric mean covariance during `fit`. If you fit on all 871 subjects and then cross-validate, every test subject contributed to that reference. Measured effect: **+4 to +6 accuracy points of pure fantasy.** `kind='correlation'` is stateless and immune, which is exactly why a leaky pipeline shows tangent "outperforming" correlation by a suspiciously large margin. If you see that gap, suspect this first.

Also provide:

```python
def vec_to_matrix(v: np.ndarray, n_rois: int) -> np.ndarray:  # inverse of vectorize
def matrix_to_vec(M: np.ndarray) -> np.ndarray:
```
Write these as an exact round-trip pair and test them — the explainability module depends on mapping feature indices back to ROI pairs, and an off-by-one here silently corrupts every brain figure in the paper.

**Test:** `test_no_leakage.py::test_connectivity_fit_size` (see §7).

### 4.5 `data/graphs_brain.py`

Builds one PyG `Data` per subject. Graph-level classification.

```python
def build_brain_graphs(
    conn: np.ndarray,               # (N, R, R) — already fold-safe
    y: np.ndarray,                  # (N,)
    node_feature: str = "profile",  # profile | profile+coords | identity | profile+identity
    edge_strategy: str = "topk",    # topk | knn | threshold | dense
    edge_param: float = 0.10,       # top 10% of |weights|, or k for knn
    use_abs: bool = True,
    self_loops: bool = False,
    coords: np.ndarray | None = None,
) -> list[Data]:
```

Per subject:

```python
A = conn[i].copy()
np.fill_diagonal(A, 0.0)
W = np.abs(A) if use_abs else A

if edge_strategy == "topk":
    k = int(edge_param * W.size)
    thr = np.partition(W.ravel(), -k)[-k]
    mask = W >= thr
elif edge_strategy == "knn":
    idx = np.argsort(-W, axis=1)[:, : int(edge_param)]
    mask = np.zeros_like(W, bool)
    np.put_along_axis(mask, idx, True, axis=1)
    mask = mask | mask.T                       # symmetrise
elif edge_strategy == "threshold":
    mask = W >= edge_param

edge_index = torch.tensor(np.array(np.nonzero(mask)), dtype=torch.long)
edge_attr  = torch.tensor(A[mask], dtype=torch.float).unsqueeze(-1)   # SIGNED weight
x          = torch.tensor(A, dtype=torch.float)                       # (R, R) profile
data = Data(x=x, edge_index=edge_index, edge_attr=edge_attr,
            y=torch.tensor([y[i]]), sub_id=..., site=...)
```

**Gotchas**
- **Threshold on `|weight|`, keep the sign in `edge_attr`.** Negative correlations are biologically meaningful; discarding them loses real signal, but treating -0.8 as a weak edge is also wrong.
- **A dense graph learns nothing.** At `edge_param=1.0` every node sees every node and message passing degenerates to a global average. If your GNN is stuck at ~53%, print the mean node degree first — that is the bug 40% of the time.
- Node feature dim = `R`, which is 200 for CC200. That is a *large* node feature. Consider a linear projection to 64 as the first layer.
- `sub_id` and `site` must be carried on the `Data` object so you can group by site downstream. PyG collates extra attributes only if they're tensors or scalars — store `site` as an integer code, not a string.

**Test:** `test_graph_builders.py` — edge_index max < R, symmetric when expected, degree > 0 for every node, mean degree within 20% of the requested density, no NaN in `x`.

### 4.6 `data/graphs_pop.py`

One graph for the whole cohort. Node = subject. Node-level, transductive.

```python
def build_population_graph(
    X: np.ndarray,                    # (N, F) reduced connectivity features
    pheno: pd.DataFrame,
    y: np.ndarray,
    train_mask, val_mask, test_mask,
    sim_metric: str = "correlation",
    pheno_terms: tuple = ("sex", "site", "age"),
    age_tol: float = 2.0,
    knn: int = 10,
) -> Data:
```

Edge weight:

```
A_ij = sim(x_i, x_j) * ( 1[sex_i == sex_j] + 1[site_i == site_j] + 1[|age_i - age_j| < age_tol] )
```
then sparsify with kNN. `X` here must already be dimensionality-reduced (ANOVA F-test top-k or PCA) **fit on the training mask only** — 19,900-dim node features on 871 nodes will not train.

**Gotchas**
- **Transductive ≠ leaky, but it's close.** Test node *features* are visible, test *labels* are not. State this in the paper. Verify in code that `y[test_mask]` is never used in loss computation.
- **The `site` phenotypic term breaks LOSO.** Under leave-one-site-out, if edges require matching site, the held-out site becomes a disconnected component with zero informative neighbours and the model predicts the majority class. Handle this explicitly: run population-graph LOSO both with and without the site term, and report it. It is a real finding, not a bug to hide.
- Semi-supervised loss masks the loss, it does not mask the graph. Message passing still flows through test nodes — that is the point of the formulation.

### 4.7 `harmonize/combat.py` — **leakage-critical**

```python
class ComBatTransformer(BaseEstimator, TransformerMixin):
    """Fit ComBat site parameters on training folds; apply to test.
    covars must preserve biological variance: age, sex, diagnosis."""
    def fit(self, X, y=None, batch=None, covars=None): ...
    def transform(self, X, batch=None): ...
```

Use `neuroCombat` + `neuroCombatFromTraining`, or `neuroHarmonize`'s `harmonizationLearn` / `harmonizationApply` (cleaner fit/apply separation — prefer it).

**The hard problem, which you must document rather than paper over:** under LOSO, the test site was *never seen during fit*, so no site parameters exist for it. Three options, all defensible, pick one and justify:

1. Leave the test site un-harmonized (honest; measures ComBat's value on the training distribution only)
2. Estimate the test site's parameters from its own unlabeled data (transductive harmonization — must be declared)
3. Use a reference-batch ComBat and map the test site to the reference

**This limitation is a paragraph in your Discussion, and a good one.** It is also the strongest argument for the adversarial site-invariance approach, which has no such problem.

### 4.9 `models/` 

`registry.py` maps a config string to a constructor so `02_run_experiment.py` never contains an `if model == ...` chain.

**`classical.py`** — returns sklearn `Pipeline` objects, always with the connectivity transformer *inside*:

```python
def build_svm(cfg):
    return Pipeline([
        ("conn",   ConnectivityTransformer(kind=cfg.conn.kind)),
        ("scale",  StandardScaler()),
        ("select", SelectKBest(f_classif, k=cfg.select_k)),
        ("clf",    LinearSVC(C=cfg.C, max_iter=10000, class_weight="balanced")),
    ])
```
The whole point of the `Pipeline` is that `SelectKBest` and `StandardScaler` are then automatically fold-safe. Feature selection outside the CV loop is the second most common leak after tangent-space fitting; the `Pipeline` makes it structurally impossible.

**`gnn_graph.py`** — one class, architecture selected by a string:

```python
class BrainGNN(nn.Module):
    def __init__(self, in_dim, hidden=64, n_layers=3, conv="gat", heads=4,
                 pool="mean", dropout=0.5, n_classes=2, edge_dim=1):
        # conv in {gcn, gat, gin, sage, cheb, transformer}
        # pool in {mean, max, sum, mean+max, topk, sag}
    def forward(self, data, return_attention=False): ...
```
Keep `return_attention=True` plumbed from day one — retrofitting it into a trained model later is painful, and the interpretability chapter depends on it.

Starting hyperparameters that actually work on this data (small N, high dim):
- hidden 32–64, layers 2–3 (4+ over-smooths at R=200)
- dropout 0.4–0.6, weight decay 5e-4 to 1e-3
- lr 1e-3 with `ReduceLROnPlateau`, batch 32–64
- early stopping on **validation AUC**, patience 20, min 30 epochs

**`hybrid.py`**

```python
class HybridModel(nn.Module):
    """brain-graph encoder -> 64-d embedding -> population GNN -> node labels.
    Optional GradientReversal -> site discriminator for site-invariance."""
    def __init__(self, encoder_cfg, pop_cfg, lambda_adv=0.0, n_sites=17): ...
```
Build and validate **stage-wise first**: (1) train the encoder as a plain graph classifier, (2) freeze it, dump embeddings, (3) train the population GNN on those embeddings. Only once both halves work independently should you attempt end-to-end. Debugging a broken end-to-end hybrid with an adversarial head is a week you don't have.

For the GRL, ramp `lambda_adv` from 0 → target over the first ~30% of epochs. A constant large λ from epoch 0 makes the encoder collapse to a constant.

## 8. Sanity checks that run before you believe any number

Put these behind `python scripts/02_run_experiment.py +sanity=true`.

| Check | Expected | If it fails |
|---|---|---|
| Label shuffle | bal_acc ≈ 0.50 | **Leakage.** Stop everything. |
| Single-batch overfit (32 samples) | train acc → 1.00 | Broken architecture, lr, or loss |
| Random node features | large accuracy drop | Model is reading the graph structure only, or nothing |
| Empty-graph ablation (no edges) | ≈ MLP-on-features performance | Quantifies what the topology actually contributes — a great paper table |
| Mean node degree printed | 10–40 for CC200 | Dense graph → message passing is a global average |
| Sex-prediction control task | ~0.80+ AUC | Sanity: the features carry *some* real signal. If sex is also at chance, the data pipeline is broken, not the ASD task |
| Site-prediction control task | high AUC expected | Quantifies how strong the site confound is — cite this number in Discussion |

The last two are cheap, take an hour to implement, and both produce content for the paper.

Cache keyed by hash:

- `data/cache/conn_{atlas}_{kind}_{foldhash}.npy` — **only for stateless kinds** (correlation). Tangent and partial-with-shrinkage are fold-dependent; caching them by anything other than fold identity reintroduces the leak you just eliminated.

Rough runtimes to plan against (T4, 871 subjects, CC200):
- Connectivity build, all subjects: ~1–2 min
- Classical model, 10-fold × 5 seeds: seconds to ~2 min (CPU, parallelise with `n_jobs=-1`)
- GNN, one fold, 200 epochs: ~30–90 s
- GNN, 10-fold × 5 seeds: ~30–60 min
- Full grid (12 models × 3 atlases × 3 conn × 2 protocols × 5 seeds): **queue it, don't watch it.** Run classical models on CPU in parallel with GNNs on GPU.

## 10. Common bugs, ranked by how much time they will cost you

| Symptom | Most likely cause |
|---|---|
| Accuracy > 85% | Tangent/ComBat/feature-selection fitted outside the fold |
| Accuracy stuck at 53% | Graph too dense (check mean degree) or all-constant node features |
| Loss becomes NaN at epoch 1 | Zero-variance ROI → NaN in correlation; or lr too high |
| Train 100%, val 55% | Expected at N=871 with 20k features — reduce hidden dim, raise dropout/weight decay |
| Results differ between runs | Unseeded DataLoader shuffle, or non-deterministic PyG scatter |
| LOSO std ±20 points | Tiny sites. Report per-site n; weight the mean |
| Population GNN predicts one class under LOSO | Held-out site disconnected because edges require matching site |
| Model beats baseline on one seed only | Not a result. Always ≥3 seeds |
| Explainability ROIs look random | Check `vec_to_matrix` round-trip; also check saliency stability across folds |
| PyG shape errors after collation | Custom `Data` attributes must be tensors/scalars, not strings |
